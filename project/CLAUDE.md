# تعليمات المشروع — منصة متابعة رئيس القطاع

## قواعد الأداء (إلزامية في كل تعديل)
1. لا تضع كل الصفحات والمنطق والبيانات في ملف واحد ضخم — قسّم إلى Components/DCs حسب الصفحة أو الميزة.
2. لا تُحمّل بيانات التقارير والجداول والتقويمات عند فتح الموقع؛ حمّلها فقط عند فتح صفحتها/تبويبها (lazy).
3. لا تعرض الجداول الكبيرة كاملة دفعة واحدة — استخدم Pagination أو "عرض المزيد" أو الفلاتر.
4. الصفحة الرئيسية تعرض ملخصات فقط، لا تفاصيل الأقسام.
5. تأكد من عدم وجود Infinite Loop أو Event Listeners مكررة.
6. حافظ على سرعة التنقل بين الصفحات.

## سبب التجمّد السابق (لتفاديه)
- أي قيمة تُعاد من `renderVals()` كـ **React element** عبر ثقب `{{ ... }}` مباشر (مثل createElement أو كائن يتغيّر مرجعه كل render) تُسبّب Infinite re-render في الـ runtime.
  - الحل: لا تُمرّر عناصر React عبر الثقوب؛ استخدم نصوصاً/أحرفاً أولى (initials) أو `<img>`، أو خزّن الكائن مرة واحدة على `this._x` (identity ثابت).
- أمثلة أصلحناها: `formInput` (خُزّن على `this._formInput`)، و`project.avatarEl` / `project.managerAvatarEl` (استُبدلت بأحرف أولى).
- **مهم (تفاصيل المشروع بالتبويبات):** وجود عدة حقول `<textarea value="{{ ... }}">` مضبوطة (controlled) داخل عدة `<sc-if>` مجاورة في نفس القالب سبّب تجمّداً عند التحميل. الحل المطبَّق: جعْل textarea نافذة «إضافة توجيه» غير مضبوط (بدون `value`، مع `onInput` فقط) — الوظيفة تبقى سليمة لأن المسودة تُصفّر عند الفتح وتُغلق النافذة بعد الحفظ. عند إضافة نوافذ/حقول جديدة تجنّب تكديس عدة textarea مضبوطة داخل sc-if متجاورة.

## بعد كل تعديل
- افتح الملف وتأكد أنه يُحمّل بدون تجمّد وبدون أخطاء Console.
- إذا كان التعديل سيزيد الحجم أو يُبطئ التشغيل، أخبر المستخدم أولاً واقترح بديلاً أخف.

## القاعدة المعمارية للأداء (جذر المشكلة المتكرّرة)
`renderVals()` يُنفَّذ في **كل** عملية render ولكل الصفحات. أي حساب ثقيل يُوضع مباشرةً في مساره العام = بطء دائم يظهر على كل الصفحات (ومنها الرئيسية)، وقد يظهر الـHTML كنص قبل اكتمال التهيئة.

**القاعدة الإلزامية لأي قسم/ميزة جديدة:**
1. غلّف حساب بيانات كل صفحة بـ `if(S.page==='<الصفحة>'){ ... }`.
2. عرّف المتغيّرات المُعادة لتلك الصفحة بـ `let x=null;` **قبل** الشرط، وأسنِدها **داخله** فقط. (الثقب `{{ x }}` مع `null`/`undefined` لا يرسم شيئاً — آمن، لأن القالب محميّ أصلاً بـ `<sc-if isPage>`.)
3. الصفحة الرئيسية: ملخصات/أرقام خفيفة فقط — لا اشتقاق جداول أو تقاويم أو تعارضات.
4. لا حساب تعارضات الإجازات أو أي بيانات ثقيلة إلا داخل `if(S.page==='leaves')`.
5. القوائم الكبيرة: Pagination / «عرض المزيد» / فلاتر — لا تبنِ كل الصفوف في DOM دفعة واحدة.
6. ممنوع تمرير عناصر React عبر ثقوب، وممنوع تكديس حقول `value` مضبوطة داخل `sc-if`/`sc-for` متجاورة، وممنوع ثقب نمط كامل `style="{{ x }}"` بقيمة من نطاق خارجي داخل `sc-for` (يُستخدم interpolation أو خاصية على عنصر الحلقة `{{ r.style }}`).

**خطة إعادة الهيكلة التدريجية (كتلة واحدة لكل خطوة، مع اختبار متصفح نظيف بعدها):** مركز التقارير (`rep`) ← التدقيق (`aud`,`aud.fam`) ← سجل التقارير (`reg`) ← المالية (`finReport`,`finEntityPanel`) ← تقويم الاجتماعات (`cal*`) ← مهام المحاضر (`mt`) ← مهام المكتب/الكانبان (`ot`,`oColumns`). تنبيه: بعض المخرجات (مثل `regActions`/`mtaskActions`/`otaskActions`/`auditActions`) تُدمج في صفحة «الإجراءات» — يجب إبقاء ما تحتاجه تلك الصفحة غير مغلَّف أو إعادة حسابه بخفّة.

## بعد كل تعديل (تكرار مهم)

## قسم إجازات الفريق (جديد)
- صفحة «إجازات الفريق» تعرض: بطاقات ملخصة، «تعارضات تحتاج انتباه»، وعرضين (حسب الفئة + جدول) مع فلاتر ونافذة جانبية بأزرار (اعتماد/رفض/ملاحظة/بديل/طلب تعديل/تمت المراجعة).
- النطاق: فريق المكتب + مدراء القطاع فقط (لا موظفين تابعين).
- **عرض التقويم مؤجَّل**: تسبّب في تجمّد عند دمجه في الصفحة الكاملة (سبب غير محسوم بدقة — يُعاد بناؤه لاحقاً بحذر واختبار بمتصفح نظيف). البيانات جاهزة (lvCalRows) عند الحاجة.
- تحذير أداء عام: اختبار التجمّد يجب أن يكون عبر متصفح نظيف (ready_for_verification)، لأن معاينة الوكيل الداخلية تتباطأ بعد عشرات التحميلات وتعطي إشارات تجمّد كاذبة.

## الحالة الحالية
- الملف الرئيسي: `منصة رئيس القطاع.dc.html` — يعمل بكامل الشاشات، وتفاصيل المشروع الآن بالتبويبات المعتمدة (نظرة عامة، الجدول الزمني/Gantt، المهام، التحديثات، المخاطر، قرارات رئيس القطاع، المرفقات) + منطق اعتماد الاكتمال (بانتظار الاعتماد → اعتماد/إرجاع/إعادة فتح).
- التبويبات مربوطة ببيانات المشروع الحقيقية وتُحسب فقط عند فتح مشروع (lazy).
